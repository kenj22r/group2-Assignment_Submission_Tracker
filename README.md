# Assignment Submission Tracker

A modular desktop and command-line application built in Python for managing, validating, and auditing academic assignments. The architecture splits application lifecycle processing, structured local state persistence, and responsive UI layers cleanly across distinct software modules.

---

## 🏗️ Project Architecture

The codebase follows a decoupled micro-package structure separating state/logic from execution interfaces:

* **`GUI/`**: Built on CustomTkinter; handles window geometries, responsive grid topologies, and high-level view mounts.
* **`Interfaces/`**: Manages pure visual presentation structures for terminal interactions.
* **`Logics/`**: Central engineering core. Coordinates transaction flows, field-level data validation rules, custom input debouncing, and search index matches.
* **`Models/`**: Handles localized serialization and file I/O operations with a JSON-flatfile database.
* **`Utilities/`**: Exposes utility functions managing shell layout mechanics and ANSI string cleanups.

---

## 🛠️ Key Technical Implementations

### 1. Robust Process Lifecycle Management
To enable rapid UI prototyping, a background watcher thread (`dev_runner.py`) uses the external `watchdog` engine to look for changes inside the source directory. Whenever files are saved, it handles hot-reloads dynamically:
* **Process Isolation**: Uses decoupled `subprocess.Popen` wrappers running target scripts via system-specific Python interpreters (`sys.executable`).
* **Soft Termination Handling**: Employs clean state checks (`.poll() is None`) to signal and await soft process closures (`.terminate()`), preventing runtime zombie processes.
* **I/O Debouncing Engine**: Intercepts double-firing file events generated by advanced text editors using inline delays (`time.sleep(0.2)`).

### 2. Native Terminal Cleanups (ANSI)
To maintain crisp CLI rendering throughout user interactions, screen clearing handles fallback commands dynamically based on the host kernel runtime platform (`nt` for Windows vs `posix` for Unix/macOS). For target error outputs, inline cursor rewrites use raw ANSI string streams (`\033[1A\033[2K`) to systematically backstep lines and wipe text buffers instantly without screen flickering.

### 3. Incremental Key Constraints & Corruption Recovery
The persistence module (`Models/open_and_save.py`) implements a relational auto-increment primary key algorithm (`AS_ID_X`). It isolates the trailing integers via token segment string splitting, queries the absolute maximal integer boundary dynamically, and auto-generates consecutive records. Structural file parsing errors are caught safely via `json.JSONDecodeError` to automatically fall back onto empty map states without system crashes.

### 4. Input Sanitization & Format Audits
All string properties are piped through data validation matrices before transaction states clear for serialization:
* Alphanumeric checking to prevent script injections.
* Hard boundary length constraint verification (max 50 characters).
* System reserved-word filters to eliminate duplicate object states.
* Calendar validation auditing string inputs using structured time mapping checks (`time.strptime(val, "%Y-%m-%d")`).
